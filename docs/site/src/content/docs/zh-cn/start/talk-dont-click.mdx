你只在 agent 会话（Claude Code 或 Codex）里做决定。建 issue、开 PR、审查、合并、关闭都由 agent 按你的指示执行，你的每个决定都记在相应的 issue 上。

<Session lang="zh-cn" />

## 每条指令就是一个目标状态

指令说的是工作要推进到哪里。agent 一直推进，到达目标、碰到[关口](/cvsm/zh-cn/concepts/gates-and-blockers/)或遇到卡点时才停。

| 你说 | agent 做什么 |
|---|---|
| “我们计划一下这个研究”、“我想研究 X” | 按 `plan` skill 和你讨论，起草研究、它的规格和子 issue；等你说“发布”才建 issue |
| “发布” | 按波次建父 issue 和子 issue，并记下 Decision |
| “做 #11” | 把代码任务推进到待合并：检查全绿、当前 head 有 `Verdict: pass`；任务写了 `Merge: agent` 就推进到合并完成 |
| “合并”，或“合并 #13” | 用 `python .github/scripts/merge.py <PR> --human` squash 合并当前 head |
| “把 #10 推到待分析” | 一直推进到研究 #10 的子 issue 全部关闭 |
| “继续” | 推进到下一个关口 |
| “看看等我的” | 读 GitHub 上的状态，列出带 `needs-decision` 的 issue 和待合并的 PR |

你明确下的指令本身就算批准，agent 不会再问一遍。“合并 #13”就是批准合并 #13；“`#10` 下结论：……”就是批准带着这个结论关闭研究。

## 每个决定都有记录

你做的每个决定，agent 都在 issue 上记成一条评论：

```text
Decision: <选项> — <一行理由>
```

发布研究、合并 PR、超出预算后继续，都会留下一条 `Decision:`。讨论本身不留存，只有决定和结论写到 GitHub 上。

## 每次停下都汇报三行

无论因为什么停下，agent 都只汇报三行，带链接：

```text
Done: <完成了什么>
Waiting for you: <等你做什么，没有就写无>
Next: <接下来做什么>
```

<Aside type="caution" title="需要你的地方">
关口和卡点都出现在 “Waiting for you” 这一行。待合并的 PR 不另打 label：PR 本身就是请求，你问“看看等我的”时它会列出来。
</Aside>

## 你不在会话里时

agent 在你不在时遇到卡点，会给 issue 打上 `needs-decision`，贴一条四行的卡点评论，然后转去做别的就绪任务。你之后在会话里答复，agent 再去掉这个 label。见[关口与卡点](/cvsm/zh-cn/concepts/gates-and-blockers/)。

## 同时开几个会话

可以同时开几个会话，各做一件事。认领任务就是用 `gh issue develop` 建一个关联分支。已经认领的任务，除非指令点名，别的会话不会接手，所以两个会话不会做同一个任务。

会话本身什么都不存。每次状态变化都当场写回 GitHub 或 git，会话随时可以断；新会话说一句“继续 #11”就能接上。

<Aside type="tip">
CVSM 自己的 skill 用中文讨论和汇报。接入的项目在 AGENTS.md Project 一节的 `Language` 一行写明面向人的文字用什么语言。`Decision:`、`Verdict:` 这类格式关键字保持英文。
</Aside>
